# ADR-001: 读写分离共享包(参照 esp-rw-java)

**状态**: Accepted(默认关闭,按服务逐个启用)

## 背景

PLPP 读多写少(课程/知识点/运营报表查询占比高),单主库 CRDB 写读混流在高并发读下与写争抢连接。ESP 项目已有成熟读写分离共享包 esp-rw-java(`RoutingDataSource` + `@DataSource` 注解/切面 + ThreadLocal 路由 + 双 Hikari 池),经生产验证。PLPP 的 CRDB 3 节点集群已有读端点(`cockroachdb-read` svc, NodePort 26267,follower/replica),写端点为主 svc(26257)。

## 决策

在 `platform-common` 新增 `com.platform.common.rw` 包,**参照 ESP esp-rw-java 模式落地**(方法论来源: ESP SAD"读写分离"章节):

- `RoutingHolder`: ThreadLocal 路由标记,默认 WRITE(未注解方法走主库,安全默认)
- `ReadWriteRoutingDataSource extends AbstractRoutingDataSource`: `determineCurrentLookupKey()` 读 RoutingHolder
- `@ReadOnly` 注解(方法/类级)+ `ReadOnlyAspect` AOP: 入口 set READ、出口恢复/清理,支持嵌套(prev=READ 恢复不 clear,prev=WRITE clear 防 ThreadLocal 泄漏);**已有写事务时强制 WRITE 并跳过 READ 标记**(同事务内不能安全切换连接——事务绑定首个 getConnection 的连接,后续标记不生效),即仅对无事务/只读事务方法生效
- `ReadWriteDataSourceProperties`(app.rw.*): write-url/read-url/凭据/池参数,`app.rw.enabled` 默认 **false**
- `ReadWriteDataSourceAutoConfiguration`: enabled=true 时构建 write/read 双 Hikari 池 → RoutingDataSource → `LazyConnectionDataSourceProxy` 包裹为主 DataSource;未配 read-url 自动降级单池
- 注册方式: 追加到 `platform-common/src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`(与现有 4 个 AutoConfiguration 一致)

CRDB 场景: read-url 指向 `cockroachdb-read` svc / follower 节点,write-url 指向主 svc。

## 后果

- 正面: 读流量卸载到副本;默认关闭零风险;单池降级保证缺配置时可用;与 JdbcTemplate/JPA 透明兼容。
- 负面/约束: 同事务内路由不生效(切面已强制 WRITE 并注释说明);CRDB follower 复制延迟导致写后读旧值 → 用 `@ReadOnly(forceWrite=true)` 走主库;异步链需显式传递 ThreadLocal(注释 TODO: 评估 ScopedValue)。
- 测试: RoutingHolderTest(4)/ReadOnlyAspectTest(5)/RoutingDataSourceTest(4),共 13 用例,jacoco 门禁通过。

## 备选

1. **每个服务自建读写数据源** —— 违反"公共能力共享包优先(≥2 服务共用必下沉)"铁律,否决。
2. **应用层双 DataSource 手动注入(writeTemplate/readTemplate)** —— 侵入业务代码,无注解透明性,否决。
3. **CRDB 内置 follower read(`SHOW EXPERIMENTAL ... FOLLOWER_READS`)** —— 需要 SQL 级显式声明,与现有 JPA/模板路径不透明,且失去连接池级隔离,否决(可作为将来补充)。
4. **数据库代理层(如 HAProxy 按用户分流)** —— 运维复杂度转移到网络层,无法按业务语义(方法级)路由,否决。
